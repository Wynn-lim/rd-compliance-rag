把 `kb_src/01_知识库全量`（77 个 md、14 个模块、70 个知识条目）做成一个
**分层检索 + 带出处**的问答系统。

施工依据：`kb_src/01_知识库全量/00_总纲/06_知识库Agent构建步骤提示词.md`（v1.0）
与 `05_知识库使用提示词.md`（v1.0，系统提示词正本）。

## 2. 快速开始

```bash
cd E:\code\rd-rag

# 1) 建索引（分块 + BM25 词表 + 向量；默认 bge-m3，本机用的是 bge-small-zh-v1.5）
RAG_DENSE_MODEL=BAAI/bge-small-zh-v1.5 python -I scripts/build_index.py

# 2) 命令行问答
RAG_DENSE_MODEL=BAAI/bge-small-zh-v1.5 python -I scripts/ask.py "委托境外研发费用的加计基数怎么算？"

# 3) 看检索过程
RAG_DENSE_MODEL=BAAI/bge-small-zh-v1.5 python -I scripts/ask.py --explain "高企研发费用占比分几档？"

# 4) 导出完整 prompt（无 key 时最有用的用法）
RAG_DENSE_MODEL=BAAI/bge-small-zh-v1.5 python -I scripts/ask.py --dump-prompt "研发支出资本化五个条件？"

# 5) 评测
RAG_DENSE_MODEL=BAAI/bge-small-zh-v1.5 python -I scripts/run_eval.py --top-k 8

# 6) Web 界面（本机部署，打开 http://127.0.0.1:8000）
RAG_DENSE_MODEL=BAAI/bge-small-zh-v1.5 python -I web/server.py --port 8000
```

**重排模型默认关闭**（`RAG_RERANK_MODEL=__disabled__`）：bge-reranker-v2-m3 已下载到本机缓存，
但 CPU 上单问约 28 秒，不适合交互。要用就把该变量删掉，或设成模型名。

## 给同一 WiFi 的人用

不需要服务器。三个 `.bat` 已按你机器上「竞品情报工作台」的成熟模式做好：

| 文件 | 作用 |
|---|---|
| `启动_局域网.bat` | 启动服务，绑定 `0.0.0.0`，打印内网地址 |
| `一键修复访问.bat` | **右键 → 以管理员身份运行**。修防火墙，见下 |
| `给同事的地址.bat` | 显示并复制 `http://192.168.1.166:8000` |

### 为什么必须跑一次「一键修复访问」

Windows 防火墙默认策略可能是 `BlockInboundAlways`——**这个值会让所有放行规则失效**，
只加端口规则是没用的。脚本按顺序做四件事：

1. 三个网络配置（域/专用/公用）的入站策略改为 `BlockInbound`
2. 放行 TCP 8000 入站（`profile=any`）
3. 当前网络设为「专用」（公用网络限制更多）
4. 确认服务在监听，不在则启动

不改注册表、不加开机启动、不动其他设置。要撤销就删掉名为「研发合规知识库 8000」的规则。

### 访问控制

知识库含客户案例与 IPO 问询细节，所以开了局域网就配了门：

- 账号密码在 `web/auth.json`（已加入 `.gitignore`，不进版本库），改完重启生效
- 默认 `zhishi` / `kb2026`，**请务必改掉**
- 未登录访问首页 302 到登录页；`/api/*` 返回 401；`/api/health` 保持公开供自检
- session 用 HMAC 派生 token，`HttpOnly + SameSite=Lax`；重启服务不需重新登录
- 界面右上角有「退出」

### 限制（说清楚，免得出问题）

- **只在这一个 WiFi 内有效**。换个网络、手机开流量、人在公司连访客 Wi-Fi，都不通
- 你电脑关机或休眠，服务就停
- 地址里的 `:8000` 不能漏，且别在微信里直接点开（用 Edge/Chrome）
- 路由器若开了「AP 隔离 / 客户端隔离」，同 WiFi 设备也互不相通——这种情况无解，
  只能换路由器设置或走公网方案

`-I` 是隔离模式（防止当前目录下的同名 .py 劫持标准库）；Windows 上必须显式
`reconfigure` 输出编码，脚本里已处理。

## 3. 分层检索是怎么做的

这是全项目最值钱的设计，来自施工规格 §2.2／§3.3。

### 3.1 四层 + 治理层

| 层 | 文件 | 检索时的角色 |
|---|---|---|
| `route` | `00_总纲/03_条目索引.md` | 先定位「该读哪个条目」；其命中反推 M 编号，给知识层加权 |
| `knowledge` | `01`～`12` 模块 70 个 `M*.md` | 正文主体 |
| `errata` | `00_总纲/02_勘误记录.md` | **单独分块、单独索引**，防污染（见 3.3） |
| `ledger` | `00_总纲/01_政策文件总台账.md` | 唯一能答「这条政策还有效吗」的层 |
| `method` | 总纲／使用提示词／施工规格 | 方法论 |
| `log` | `00_总纲/04_更新日志.md` | 变更流水，**降权**，不作知识源 |

`99_收件箱`（html 每日简报）与 `13_内容产品化`（空）不入索引。

### 3.2 链路

```
问句
 ├─ 意图路由 → 决定检索哪些层（时效→台账；某说法对不对→纠错层加权）
 ├─ 中文分词（jieba + 文号/M编号/E编号/百分比 原样保护）
 ├─ BM25 top-60  ┐
 ├─ bge 向量 top-60 ┘→ RRF 融合 → top-40
 ├─ 路由反推：从路由层命中块抽 M 编号，给对应知识层块 +0.05
 ├─ 启发式重排：文号精确命中 / M、E 编号命中 / L3-L4 状态 / 层权重 / 长度惩罚
 └─ bge-reranker 交叉编码器重排 → top-8
```

### 3.3 纠错层为什么单独返回

施工规格原话：「`02_勘误记录.md` 是『纠错层』……必须单独分块、单独索引，
不能和知识正文混在一起，否则检索结果会互相污染。」

实现上分两步：

1. **物理隔离**：纠错层单独分块、单独建索引，元数据 `layer="errata"`；
2. **逻辑隔离**：默认**不参与主结果排名**，而是作为 `warnings` 附加返回
   （最多 3 条，需过相似度门槛）。它回答的是「这个说法对不对」，
   不该挤占「正文答案」的名额。

只有问题本身就在问勘误/铁律/检查项（或含 E 编号）时，才并入主结果。

> 实测：早期把纠错层并进主结果，10 题基线命中率从 10/10 掉到 9/10——
> 它把 M07-01 挤出去了。改成附加返回后两者兼得。

### 3.4 拒答：三道门

「查不到就说查不到」是本项目的硬规则，但单纯靠向量相似度分不开
「问的是库外事物」和「问的是库内事物」（实测库外问题也能到 0.56~0.60）。
所以用三道门，全部通过才算相关：

1. **向量余弦 ≥ 0.62**（实测库内 0.63~0.73，库外 ≤0.60）；
2. **或 BM25 ≥ 12**（问句含文号/M 编号时，即使语义分低也算强命中）；
3. **实体覆盖 ≥ 0.5**：问句里的专有实体（如「澳大利亚」「R&D Tax Incentive」）
   必须有一部分出现在检索结果里。

第 3 条是最可靠的一道——问句问的是库外事物时，它的专有实体在库内覆盖率是 0%。

## 4. 分块规则

| 规则 | 实现 |
|---|---|
| 按 `##` 节切 | `chunker.py::split_document` |
| 每块 ≤1000 字 | `MAX_CHUNK_CHARS=1100`（留余量），实测 max 1506、p95 1056 |
| 超长节先按 `###` 子节切，再按空行分段 | `_split_section` |
| **表格整块不拆** | `_table_blocks` 把连续表格行合成一个块 |
| 表格被空行切断后续块补回表头 | `_table_blocks` 记录并前插表头 |
| 单个超长表格按行组切分、重复表头 | `_split_oversized_table` |
| 单个超长行（实测有 3.2 万字一行）按 `／；，、` 切，保持单元格数 | `_split_long_row` |
| 四字段元数据 | `文件名 / M 编号 / 层级 / 节标题`（另加模块、状态、文号、E 编号、日期） |

元数据里的 `doc_ids`（文号）是从正文正则抽的，用于「问题含文号 → 精确命中加成」，
也用于前端出处展示。

## 5. 评测

```bash
python -I scripts/run_eval.py --top-k 8
```

四指标（交接文档 §6.4 的建议方案）：

| 指标 | 怎么测 | 当前结果 |
|---|---|---|
| 检索命中率 | 10 题基线里，期望 M 条目是否进 top-k | **10/10** |
| 出处正确率 | 关键内容（比例、条件、文号）是否出现在检索上下文 | **9/10** |
| 口径不混 / 抗污染 | 5 例 badcase 的 E 编号是否被检索到 | **4/5** |
| 拒答准确率 | 3 条库外问题是否被判「库内暂无」 | **3/3** |

单元测试 12/12 通过（`tests/test_rag.py`）。

当前用的是 `BAAI/bge-small-zh-v1.5`（512 维，本机已缓存，单问检索约 25 ms）。
换 `bge-m3` 需要重新建向量索引，预期检索与重排都会更好。

**已知未过项**：
- BC-04（研发费用监管有哪几个口径）：纠错层召回的是 E-064/E-717 等，
  E-005（「四口径」应校正为「五口径」）排第 6。bge-small-zh 在这个问句上的
  语义上限，未为过单个用例去调参。正确结论（五口径含 R&D 统计）仍在检索上下文中，
  系统不会照抄「四口径」错答。
- Q6 之外无其他基线缺口；Q6 已在分词器修复后通过。

## 界面

深色「墨青仪器台」风格，设计取向是**法规溯源工具**而非通用聊天框：

- **朱砂红 `#C8442E`** 只用于「已核实 / 权威 / 主操作」——取自中国公文的印章红
- **松石绿 `#4A9C85`** 专属纠错层（"我们抓到了错误"）
- 暖白 `#E6E2D9` 正文（台灯下的纸，不是纯白）；标题宋体系、正文微软雅黑、编号等宽
- **出处登记簿**是版面主角：文号 / M 编号用等宽 14px 作最大字，层色条编码层级，
  匹配分渲染成带刻度的仪表读数
- 出处原文按 markdown 精简渲染（表格、粗体、行内代码、引用），不裸露 `**` 与 `|---`
- 背景一层 1.4% 不透明度的格纹——因为它本来就是台账

已做：响应式（<1000px 单列）、键盘焦点可见、`prefers-reduced-motion` 降级、
暗底对比度达标。剪贴板 API 在本地 http 下不可用时自动弹手动复制框。

## 7. 纪律（本项目不可违反的四条）

1. 引用必带**文号 + 发文机关 + 官方链接 + 核实日期**；无法溯源标「⚠️待核实」。
2. **绝不凭记忆填写**文号、比例、金额、日期。
3. **只有真实且可溯源的内容才允许入库**；传闻只进勘误，不进正文。
4. **没有系统就不报准确率**，没有原文就说没有原文。

施工方只负责「搭」，不改知识。`kb_src/` 是只读输入。
